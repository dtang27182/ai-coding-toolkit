# Define and Confirm Design Guidelines

Fill only the `Design Guidelines` section in the initialized `<outputDirectory>/<feature>/<feature>.hld.md`, using the initial user request.

Use concise bullets to define only these two components of the HLD's level of abstraction:

1. **Requirements:** Specify what belongs in `High Level Requirements` versus `Detailed Requirements`, based on the level of detail needed to guide the design versus implement it.
2. **Design:** Briefly describe the general level of abstraction at which the design should be written. Exclude error handling paths unless explicitly requested by the user.

Do not include general design principles, desired behavior, scope, assumptions, constraints, or other content that belongs in `High Level Requirements`.

When the request makes these abstraction choices clear, proceed without confirmation. If any are unclear, present the proposed guidelines, explain the uncertainty, and ask the user to confirm or revise them. Wait for confirmation or clarification that resolves the uncertainty before filling other sections.
